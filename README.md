# service-integration

Плагин Claude Code для интеграции с нашими сервисами. Два режима:

- **Подключиться** — в вашем репозитории. Скилл находит `docs/integration` и
  `reference/openapi.json` нужного сервиса, определяет вашу роль (например, кассовое ПО или
  интегратор), строит план по чеклисту готовности, пишет клиент и тесты в стиле репозитория
  и в конце выдаёт, что осталось и какие вопросы задать команде сервиса.
- **Задокументировать** — в репозитории сервиса. Скилл находит внешние API, проходит каждый
  сценарий по коду, пишет `docs/integration` по общему каркасу, собирает `openapi.json` из кода
  (со скриптом и тестом против устаревания) и перечисляет дефекты, найденные по ходу.

## Установка

```
/plugin marketplace add https://github.com/yer9ali/service-integration.git
/plugin install service-integration@service-integration
```

Обновление: `/plugin update service-integration@service-integration`.

## Вызов

Все аргументы необязательны: без них скилл сам определит режим и спросит, чего не хватает.

- `/service-integration` — скилл спросит режим и сервис;
- `/service-integration docs` — задокументировать текущий репозиторий-сервис;

Подключиться (из корня репозитория, который интегрируется):

- `/service-integration ofd` — интеграция с ОФД Metrix, роль скилл спросит или определит сам;
- `/service-integration ofd касса` — сразу с ролью;
- `/service-integration ../fdo_api` — по локальному клону сервиса;
- `/service-integration <git-URL>` — сервис, которого нет в реестре.

При конфликте имён используйте `/service-integration:service-integration`.

## Какие сервисы поддерживаются

Реестр — `plugins/service-integration/skills/service-integration/reference/services.json`.

| Имя | Сервис |
|---|---|
| `ofd` | ОФД Metrix (fdo_api) |

Нужен доступ на чтение к репозиторию сервиса: скилл читает документацию оттуда.

## Как подключить свой сервис

1. В репозитории сервиса запустите `/service-integration docs`: скилл оформит
   `docs/integration` по каркасу
   (`plugins/service-integration/skills/service-integration/reference/docs-contract.md`,
   образец — `docs/integration` в fdo_api) и выдаст строку для реестра.
2. Добавьте эту строку в `services.json` и поднимите версию плагина в `plugin.json`.

## Что скилл не делает

- Не просит и не хранит секреты: ключи выставляются переменными окружения.
- Не коммитит и не пушит без просьбы.
- Не придумывает ручки: всё, чего нет в документации сервиса, попадает в итог как вопрос к
  его команде.
- В режиме «Задокументировать» не чинит найденные дефекты молча: описывает текущее
  поведение и выносит их в итог.
