# Каркас docs/integration

Чтобы с сервисом можно было интегрироваться этим скиллом, его документация для партнёров
устроена так. Образец — `docs/integration` в fdo_api.

```
docs/integration/
  README.md            ← точка входа
  00-basics.md         ← общие правила для всех партнёров
  10-<сценарий>.md     ← по разделу на сценарий
  20-<сценарий>.md
  ...
  reference/
    openapi.json       ← OpenAPI только партнёрских ручек, собирается из кода
```

## README.md

Обязательно:

- одна-две фразы, что это за сервис;
- таблица **«Что читать»**: колонка «Вы» (роль партнёра) и колонка «Путь» (разделы по
  порядку, ссылками). По этой таблице скилл выбирает сценарий;
- ссылка на `reference/openapi.json`.

## 00-basics.md

Общее для всех ролей:

- **TL;DR для ассистента** — главные правила списком;
- стенды и базовые URL, включая префикс пути;
- доступ: как получить ключ или токен, какой заголовок;
- формат ответа и ошибок, таблица кодов с колонкой «повторять?»;
- идемпотентность, вебхуки, правила совместимости, песочница.

## Сценарный раздел

Один каркас для всех, в таком порядке:

1. **TL;DR для ассистента**.
2. **Шаги** — вызовы по порядку, запрос и ответ, желательно диаграмма последовательности.
3. **Статусы** — все значения, конечный ли, что делать клиенту.
4. **Ошибки** — ситуация, HTTP, код.
5. **Асинхронность** — вебхук, опрос, повторная доставка.
6. **Повтор и особые случаи**.
7. **Примеры** — по ответу на каждый исход.
8. **Чеклист готовности** — список `- [ ]`. Скилл строит по нему план и итог.

## Соглашения

- Пометка **«⚠ Будет изменено»** — место, где контракт изменится; клиент должен пережить
  изменение.
- Фраза **«выдаётся при подключении»** — данные, которые партнёр получает от команды
  сервиса; скилл выносит их в список «запросить».
- Никаких «уточните у команды» и «см. код»: всё, что нужно для интеграции, написано в
  документе.
- Секреты в документах не публикуются, только способ их получить.

## Подключить сервис к скиллу

Добавьте запись в `reference/services.json` плагина:

```json
"<имя>": {
  "title": "<название сервиса>",
  "repo": "<git-URL>",
  "branch": "<ветка, где лежит актуальная документация>",
  "docs_path": "docs/integration",
  "aliases": ["<другие имена>"]
}
```
